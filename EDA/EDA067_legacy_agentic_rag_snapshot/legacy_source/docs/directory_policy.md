# ディレクトリ運用方針

## 基本方針

このコンペは通常の表データ予測ではなく、共有ドライブ内の多形式ファイルを対象にしたRAG/QA課題です。  
そのため、`data/processed` に「LLMへ渡しやすい抽出済みテキスト・表・メタ情報」を段階的に増やす方針にします。

## EDA番号の使い方

- `EDA001`: データ全体の棚卸し
- `EDA002`: 文書・表・コードの一次抽出
- `EDA003`: valid質問の分類と必要情報源の整理
- `EDA004`: 検索・回答生成の最小ベースライン
- `EDA005`以降: 書式、画像、差分比較、集計処理の強化

## 注意点

- `share.zip` の中には日本語ファイル名が多いため、パス処理ではUTF-8前提にします。
- `~$` で始まるExcel一時ファイルも含まれるため、実処理では除外候補にします。
- LLM評価で `Incorrect = -1` のため、根拠が弱い回答を無理に出すより、根拠確認を重視します。
